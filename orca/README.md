# orca

Tracked source for orca's **user config dir**, `~/.orca` — symlinked here by every
`<os>/install.sh` (`link_target`), exactly the way `pi/` backs `~/.pi`. Home Manager
does not manage it: like `pi`, `.ai` and `claude`, it is agent config that the app
rewrites at runtime, so it stays a plain symlink.

## What lands here

| path                 | tracked?                     | notes                                                                                                                                                     |
| -------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `keybindings.json`   | ✅ once it exists            | Keybinding overrides. orca writes it the first time you remap a shortcut, so it lands in the repo by itself — no install step needed.                    |
| `agent-hooks/`       | ❌ gitignored                | Generated by orca's **Agent status hooks** setting (`orca agent hooks on\|off`); regenerated on toggle and on update. Tracking it would only track drift. |
| anything else        | ❌ leave untracked for now   | Later orca versions may store more here. Look before committing — if it is machine state, add it to `.gitignore` instead.                                  |

## Do not touch `~/.config/orca/`

`~/.config/orca/` looks like the config dir but is **Electron app data**, and it
must never be symlinked into this repo or committed:

- **`orca-e2ee-keypair.json`** — the *private* Curve25519 key that secures mobile
  pairing (`src/main/runtime/e2ee-keypair.ts`: the public half is embedded in the
  pairing QR offer for ECDH). orca deliberately **refuses** to regenerate it —
  "would invalidate every paired device" — so treat it as long-lived key material.
- `agent-session-authority.key`, `orca-runtime.json` (live auth token + socket
  path), `profiles/local-default/account-session.json.enc`,
  `orca-secret-protection.json`.
- Chromium side: `Cookies`, `Local Storage`, `orchestration.db`,
  `profiles/local-default/profile-state.db`, caches, and `linux-orca-cli-shim/`
  — a per-run shim pinning a pid, a process start time and the AppImage mount's
  inode identity, i.e. dead the moment orca restarts.

orca's **Settings panes are not files at all** — they live in that Electron
storage, so they do not travel between machines. What does travel: this dir's
`keybindings.json`, plus the per-project `orca.yaml` / `.worktreeinclude` pair,
which belongs in each *project* repo (see the orca docs, "orca.yaml").
